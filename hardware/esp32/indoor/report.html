Five camera quadcopters with parts budgets below $50

Start with the Scout 110. It offers more budget margin for sourcing and revisions. Compare the Height 110 for downward ranging and the Split 110 for independent flight-control timing.

These are five unbuilt design candidates, not five qualified products. Every budget includes a camera, battery, IMU, motor drivers and guards. Supplier listings cover the camera and propulsion; other rows are explicitly marked allowances. A complete purchase under $50 has not been verified.

Frame source · Wiring and integration

One camera path and two control architectures

All five use the supplied XIAO Sense camera facing forward. The compiled camera-only sketch in the parent package produces 640 × 480 JPEG images over HTTP. The ground receiver samples at 5 fps by default and sends selected frames to the local model. Actual frame rate, focus, exposure and Wi-Fi latency need hardware measurements.

Camera → XIAO Sense → Wi-Fi /capture → drone137 latest-frame buffer → local model
Mission request → deterministic navigation/controller → bounded aircraft command
Aircraft IMU → local estimator and stabilization → motor PWM

The models run on the ground computer. Keeping one latest image and one inference in progress limits camera-path memory, but complete 8 GB operation has not been measured. An LLM never owns the stabilization timing or motor PWM.

Use the parent connection specification for each motor driver, suppression, IMU axes and battery divider. On the Sense board, remove the SD card and disable SD/microphone use. The Split flight MCU owns command expiry; the camera MCU must not reset a stale command's validity by repeating it. Sequence IDs, boot identity, command age and link-loss handling need a tested protocol.

Assembly differences

The Micro uses 7.1 mm nominal motor bores and 55 mm props. The other four use 8.6 mm bores and 65 mm props with a 110 mm motor diagonal. The original 100 mm frame is not the selected frame for these 65 mm props. All CAD assumes a 20 mm motor can, its top at z=8 mm, propeller plane near z=12 mm and feet at z=-14 mm; verify the actual hub/shaft before printing. Separate battery, carrier and camera mounts need final fitting. Guard adds upper hoops; Height adds a clear downward sensor mount; Split adds a second controller mount.

Prepared-room positioning

For the first object-search operation, use a cleared room with measured visual markers or a validated external tracking system. Keep pose estimation and movement control deterministic on the PC. The LLM chooses search actions and interprets images. Forward camera images plus an IMU are not a demonstrated indoor position solution. The Height sensor measures downward distance only; it does not supply XY hold or locate walls. Reference hardware and markers are shared equipment outside these aircraft budgets and their integration is unfinished.

What exists today

The parent camera-only firmware compiled and its camera adapter passed 12 fixture/model-stub tests in the preceding build. This catalog adds five costed designs, five parametric frame entry points and a separate SQLite proposal catalog. It adds no working flight controller, aircraft command bridge or calibrated micro-drone simulator. The existing physics registry is constrained to larger x500-derived airframes, so these proposals are not inserted as runnable profiles.

Qualification before choosing a production model

  1. Quote every BOM line and check under $50 before ordering.
  2. Print and weigh each frame; verify prop, shaft and camera clearance.
  3. Measure selected propulsion at low operating voltage; target at least 2:1 total static thrust-to-weight.
  4. Port ESP-Drone or equivalent stabilizer; verify motor order, arming, control timing and command-loss response.
  5. Implement deterministic positioning/control; LLM chooses missions and inspections, never motor PWM.
  6. Validate camera focus, frame freshness, link failure and recorded recognition on a real 8 GB computer.
  7. Run object-present and object-absent indoor missions; retain misses and false confirmations.

Compare success and false confirmations, usable image rate, command latency, control deadlines, battery sag, measured thrust and mass. Start with one aircraft and one object-present/object-absent task. Do not infer reliability from a drawing or a BOM. Flights and recognition have not been tested for any of these variants.
